# M01 · Ch02 · L01｜生产者—消费者与异步队列

> 学习日期：2026-08-27 · [返回 Ch02](README.md)

## 本次只解决一个问题

为什么 Channel 不直接调用 AgentLoop，而要通过 MessageBus 中的异步队列传递消息？

## 宏观模型

```mermaid
flowchart LR
    C1["Channel<br/>输入生产者"] --> IQ["Inbound Queue"]
    IQ --> L["AgentLoop<br/>输入消费者"]
    L --> OQ["Outbound Queue"]
    OQ --> C2["Channel<br/>输出消费者"]
```

- 生产者产生消息。
- 队列暂存消息并协调两端的处理时机。
- 消费者取得并处理消息。

`MessageBus` 使用两个 `asyncio.Queue`，并分别提供 publish / consume 方法。

## 开始前预测（学习者原话）

当 Telegram 直接调用 AgentLoop 并等待慢速模型时：

> 可能出现一直等待没有反应吗？

方向正确。更精确地说，至少当前 Channel handler 会一直被这次 Agent 执行占用；在串行接收
设计中，后续消息也可能被阻塞。队列不会让模型更快，而是把接收消息与执行 Agent 的时间线
解耦。

## `await queue.get()` 的行为

学习者正确预测：

> 暂停当前协程，把执行机会交给其他任务，有消息后再恢复。

当队列为空时，`await` 挂起当前消费者协程，事件循环可以继续运行其他任务。消息进入队列
后，这个协程被唤醒并从暂停处继续。它不是持续占用 CPU 的忙循环，也不会阻塞整个进程。

## 为什么这样设计

### 为什么不用 Channel 直接调用 AgentLoop

Channel 负责平台接入，AgentLoop 负责 Agent Turn。队列隔开两者的生命周期、延迟与暂时性
故障，使不同 Channel 可以共享同一个 Agent Core。

### 为什么使用异步等待

消息到达时间不可预测。挂起空闲消费者可以把单线程事件循环的执行机会留给有实际工作的
协程。

## 本节核心元能力

### 生产者—消费者

通过中间队列协调产生数据与处理数据的两类组件，使两端不必同时就绪。

### 协作式并发

协程在 `await` 处主动让出执行权；事件循环在等待条件满足后恢复它。

## 记忆分层

- **A：内化**：队列解耦 Channel 与 AgentLoop；空队列上的 `await` 挂起当前协程而非整个程序。
